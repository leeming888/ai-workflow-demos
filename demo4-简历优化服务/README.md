## 3. ⭐ 关键技术发现：同一模型，两个端点，行为完全不同

**MiniMax M3 的 reasoning（`<think>`）块处理，两个端点不一样：**

| 端点 | 现象 |
|---|---|
| `https://api.minimaxi.com/anthropic/v1/messages` | **content 里没有 think 块**，直接就是答案 |
| `https://api.minimaxi.com/v1/chat/completions` | **think 混在 content 里**，占 90%+ token |

### 实测证据（同一句 prompt「写一份300字的中文自我介绍」）

```
Anthropic 端点: 3.9s  raw=197   clean=197   ← 完全一致，无污染
OpenAI 端点:    20.0s raw=4291  clean=314   ← 4291 字里 4000 字是 think
```

### 为什么 OpenAI 端点会翻车

第一版实测（`run_test.py`）：
- 三步**全部撞 max_tokens 上限**（completion 全是 2500）
- STEP1 输出文件**前 104 行全是模型的内心思考，真正的简历正文一个字都没有**
- STEP3（追问清单）**输出 0 字**

**这在交付给客户时是致命的** —— 简历里塞满 `<think>We need answer Chinese...`，直接社死。

### 试过的 5 种关闭参数，全部无效

```
reasoning_effort=none      → 无效
reasoning_effort=low       → 无效
reasoning_effort=minimal   → 无效
enable_thinking=false      → 无效
thinking=false             → HTTP 400
```

**结论：不要试图关它。换端点。**

## 4. 运行方式

```bash
export MINIMAX_API_KEY=你的key

python resume_service.py \
  --input 客户简历.md \
  --output 交付目录/ \
  [--jd "岗位JD"] \
  [--endpoint anthropic]   # 默认，推荐
```

**产出**：`交付目录/成品1_简历终稿.md` · `成品2_自检意见.md` · `成品3_面试追问题清单.md` · `运行报告.md`

**依赖**：只有 Python 标准库（`json / os / re / sys / time / urllib / pathlib`）。**零第三方库、零服务器、零 API 之外的任何成本。**

## 5. ⚠️ 人工必须做的 4 件事（写进了运行报告）

AI 替代不了的部分，也是**溢价的来源**：

1. **填掉所有【待补充：XXX】** —— 填不上就删整条，**绝不留占位符**（HR 一眼看出没写完）
2. **逐条核对事实** —— AI 会把「参与」写成「负责」，必须改回真实程度
3. **检查时间线** —— 空窗期、频繁跳动，面试官第一问就是这个
4. **替换脱敏信息** —— 姓名/电话/邮箱/学校必须真实

**这 4 步 = 20-25 分钟的人工**。全流程 79 秒 + 人工 20 分钟 ≈ **30 分钟一单**。

## 8. 这个服务的真实优势（同行抄不走）

**不是"我会用 AI 改简历"，是"我知道简历里哪些东西会让 HR 直接刷掉"。**

- 实测样本里的自检意见直接命中要害：*"个人信息使用脱敏号码，削弱简历完整性"*、*"教育背景保留'某二本院校'和待补充占位符，呈现明显的未完成状态"*、*"工作经历全部使用匿名公司名称，招聘方无法判断平台和业务体量"*
- 追问清单里 M3 自己写出了这种杀手级问题：*"简历中提到的'爆款视频'到底有多爆？请给出视频链接或明确的作品标识、上线日期、播放量……如果不能公开公司账号，请说明哪些数据可以脱敏后展示"*

**这种问题清单 = 客户面试前的救命符 = 他下次还会来找你。**
