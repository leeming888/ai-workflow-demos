# Demo 3 · 文档知识库自动同步（可运行）

> **解决什么问题**：公司里有一堆 Markdown / Word / 文档，散在本地和网盘。改了本地那份，云端知识库还是旧的 —— 或者反过来，版本乱了、覆盖了、找不到历史了。
>
> **每次手动上传 = 每次都会忘 = 知识库慢慢烂掉。**

---

## 核心设计（明哥自己写的策略，业内少见）

### 同步策略：**不覆盖、不丢历史**

| 情况 | 处理 | 为什么 |
|---|---|---|
| 资料库**无同名节点** | 直接新建 | 正常情况 |
| 资料库**已有同名节点** | 先 `move-node` 到「_历史版本」文件夹**并改名加版本后缀**，再新建标准名 | **历史可回滚，标准名永远指向最新版** |

**这是很多同步工具做错的地方** —— 直接覆盖 = 旧版本永远消失 = 出事无法追溯。

### 输出同步报告 JSON
给自动化读取 → 自动化能知道"这次同步了什么、哪些失败、哪些被归档"。

### 支持选择性同步
```bash
python sync_to_library.py                    # 同步全部
python sync_to_library.py --only 99 04a      # 只同步指定前缀
python sync_to_library.py --dry-run          # 先看要动哪些（不执行）
```

**`--dry-run` 是必须的** —— 破坏性操作前先看清单，这是基本职业素养。

### 幂等
重复跑不会产生重复节点，也不会污染历史版本。

## 运行方式

```bash
python sync_to_library.py --dry-run    # 先看清单（推荐第一次都先跑这个）
python sync_to_library.py              # 实际同步
```

**配置项**（文件头常量，改成你的）：
```python
PYTHON   = r"你的 python 路径"
SKILL    = Path(r"你的 library skill 路径")
SPACE    = "你的空间 ID"
```

## 为什么这个需求真实存在（不是我想出来的）

**从明哥自己的踩坑史看**：
- 文档 nodeId **每次同步会变** → 持久引用必须用标题检索，不能存 nodeId
- 工作区会漂移 → 路径必须锚定，不能靠"取最新目录名"
- 死路径（`C:\Users\lee\WorkBuddy\...`）→ 迁到 D 盘后全线报错

**这三条都是"跑起来才发现"的，不是设计文档里写的。** 客户第一次做同步一定会踩。

## 合规声明

只做**授权范围内**的文档同步。工具不含任何凭证硬编码、不外传数据。同步前强制过敏感扫描。
